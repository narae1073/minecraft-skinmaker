# 전신 구도 대응 — 코어 렌더 성능 개선 설계

날짜: 2026-10-10 · 상태: 승인 대기 (이 문서가 승인되기 전에는 제품 코드를 건드리지 않는다)

## 배경과 의도 (why)

사용자 보고: "얼굴과 팔다리를 잘 검출 못함. 피부톤이 사진 따라가지 못하고 전부 똑같이
어두움. 바지를 아예 못 그림." 테스트 구도는 **전신**이다.

실측 결과, 세 증상은 따로따로가 아니라 하나의 뿌리를 공유한다:
**파이프라인 전체(S0/S1/S2)가 얼굴 비례 기하에 묶여 있는데, 전신에선 얼굴이 작다.**
얼굴이 작아지면 S1 밴드·S2 크롭이 몸통 일부만 잘라내고, 그 잘린 조각 위에서
분류·측정이 "정답"을 내놓아도 결과물은 깨진다. 렌더러(S3) 자체는 결정적이라
배선 버그는 없다 (`eval` valid 83/83).

### 실측 근거 (2026-10-10, out/s0_photos 97장)

- `eval`: fallback hair=80/83 (**96%**), bottom=2, skin=1. 머리색이 사실상 매번
  기본값 `#3a2a1c`으로 굳는다. 머리(384px, 최대 면적)가 전부 같은 짙은 갈색이면
  "전부 똑같이 어두움"으로 보인다.
- 프레이밍 분포(face_h/img_h): 중앙값 0.102. 0.10 미만 36장, 0.10~0.20 37장,
  0.20 이상 10장. 절반이 small-face 구도다.
- messi5.jpg(전신, 얼굴 30px): S2 크롭이 이미지 높이 64%·너비 15%만 VLM에 전달
  (다리·양팔 잘림). S1 하의 밴드 측정값 `#223896` ≒ 상의 `#213698` — 바지가
  아니라 셔츠를 재측정한 것이다.
- lena.jpg(상반신): 피부 영역(얼굴 높이 55~83%)이 입술 구간(75~85%)과 겹쳐
  화이트밸런스 게인이 클립(R=0.8)까지 갔다. 하의 밴드는 프레임 밖이라 MISSING —
  이 경우는 맨다리가 정답이다(보이는 다리가 없음).
- 포즈: 이 머신에서 mediapipe가 SIGILL로 못 돌아 `.task.disabled` 격리 중이라
  `pose`가 항상 `None`. 소매·하의 커버 측정이 매번 기권하고 VLM 답변 하나에만
  의존한다.

## 목표 (goals)

1. 전신에서 하의 enum **과** 색이 실제 다리 위치에서 오도록 한다.
   (S2 크롭이 다리를 포함 + S1 하의 밴드가 실제 하의 위치)
2. 헤어 측정 수율을 끌어올린다 (fallback 96%를 두 자릿수 후반으로).
   방향: S2 `hair_bbox` 영역에서 색을 읽는다. 얼굴 박스 기하로는 못 푼다는 건
   이미 확정된 사실이다(CONTEXT 7절).
3. 피부 앵커 오염을 막는다 (입술 겹침, 작은 샘플의 노이즈).
4. 개선을 객관 지표로 증명한다: `eval` fallback율 + 프레이밍별 리포트,
   닮음은 contact sheet 후면/UV 가이드로 사람이 판정한다.

## 목표가 아닌 것 (non-goals)

- 얼굴 정밀화. 요구사항("얼굴은 비슷하게만") 유지. 눈 2×2·입 4×1 템플릿은 손대지 않는다.
- 수염·안경 대응. v1 제외 결정 유지 (단, 측정 오염 완화는 목표 3의 범위에서).
- 포즈 모델 부활. 이 머신 제약(SIGILL) 안에서 pose-없이 동작하는 설계로 간다.
  집 Ubuntu에서 pose 경로는 별도 검증 과제다.

## 안티-골 (이렇게 되면 실패다)

- 게이트를 추가하는 것. 하드 게이트는 "얼굴 검출 실패" 하나만 유지한다.
  게이트를 쌓으면 거부율이 곱으로 발산한다.
- 정면 프리뷰로 "닮음"을 평가하는 것. 정면은 관측된 면이라 평가력이 없다.
  후면·UV 가이드 합성 패널로 본다.
- 확산/SAM/파인튜닝을 끌어오는 것. 기각 결정 유지.

## 제약 (constraints)

- 이 머신: GPU 없음, RAM 7GB, mediapipe 동작 불가. 설계는 pose 없이 완성돼야 한다.
- VLM 비용 ≈ $0.001/장. 크롭 확대·full-image 전송은 토큰(비용·지연)을 늘린다.
  프레이밍별 차등을 기본 방향으로 한다.
- `validate_image` 6개 불변식 통과 유지, 테스트 288개 그린 유지.
- Java(내곽 불투명 강제)/Bedrock(0·255) 알파 규칙 유지.

## 방향 (제안 — [내 판단] 표시가 없는 것은 대화에서 확정된 것)

- [내 판단] **S1 밴드는 cascade fallback, 하드 분기 없음**: 얼굴 비례 밴드를 먼저
  시도하고, `clip_to` 실패·픽셀 부족으로 `MISSING`이면 프레임 하부 밴드로
  넘어간다. `face_h/img_h` 임계값 같은 절벽을 만들지 않는다. 초상화는 기존
  경로 그대로(`MISSING`→S3 기본값+S2 `none` 규칙), 전신은 하부 밴드가 잡는다.
  `ObservedColors`→`resolve_bottom` 인터페이스 변경 없음.
- [내 판단] **S2 크롭은 항상 얼굴→이미지 하단 방향으로 확장**: `down` 상수
  땜질(2.2→4.0)이 아니라 이미지 하단에 걸리도록(clip이 초상화를 처리).
  좌우도 팔이 들어오도록 넓힌다. `MODEL_MAX_PX=768` 다운스케일이 토큰을
  묶어주므로 크롭 확대 자체의 추가 비용은 ≈0이다. 이중질의는 유지한다.
  단, full-image·고해상도 전송은 비용 상한 승인이 필요 (아래 "미결" 참조).
- [내 판단] **헤어 색 배선**: `extract()`에 선택 인자 `hair_bbox_px=None` 추가.
  `backend/app.py`는 `classify` 결과를 먼저 얻고(기존 순서 유지)
  `result.hair_bbox_px`를 전달한다. 이중질의 bbox 불일치는 기존 규칙
  (첫째 승리, `classify.py:169`)을 그대로 쓴다. bbox 없으면 기존 fallback 유지.
  `eval`은 VLM 없이 재현해야 하므로 고정 bbox 주입 모드를 추가한다
  (없으면 기존 경로). "hair fallback 두 자릿수" 지표는 이 모드로 잰다.
- [내 판단] **피부 앵커는 기하만, WB 상수는 불변**: 아래 경계 83%→73% 부근으로
  입술을 제외한다. `WB_CLIP`·`WB_MAX_CHROMA_DRIFT`·중앙값 로직은 손대지 않는다.
  small-face에서 샘플이 100px대로 떨어지는 노이즈는 기존 점유율·신뢰도 경로가
  받는다. 수염(non-goal)은 턱선에 그대로 있어 오염이 남는다 — 감수하고 문서에
  남긴다.
- S3 렌더 규칙(75% 파생, graphic 앞면만, 보수적 plain 폴백)은 유지한다.
- S4 후보·검증 구조(vary는 이중질의 불일치만)는 유지한다.

## 결정됨 (2026-10-10 사용자 승인): S2 전송 예산

- 전신 구도에서는 full-image 또는 고해상도 전송 허용. 장당 비용·지연 증가 감수.
- 상반신·클로즈업은 현행(이중질의+768px 상한) 유지. 프레이밍별 차등 적용.

## 빌더에게 위임하는 것

- 프레이밍 임계값, 밴드·크롭의 정확한 픽셀 정의, 피부 영역 경계값.
  전부 `eval` fallback율과 contact sheet로 증명한다.
- 상수 하나를 바꿀 때마다 이전 값과 비교하는 측정 (A-B). 기준선 없는 "개선율" 금지.
- 구현 순서: S1 밴드 → S2 크롭 → 헤어 bbox 연결 → 피부 앵커 순서를 권장한다.
  (독립적이라 병렬도 가능하지만, 측정 기준선을 공유하므로 순차 권장 — [내 판단])

## 성공 기준

- `eval` hair fallback이 고정 세트에서 50% 미만으로 떨어진다 (현재 전체 96%).
  목표치는 측정 후 재조정할 수 있으나, 방향(감소)과 절대 상한(50%)은 유지한다.
- 고정 10장(전신 4·중간 3·초상 3, `face_h/img_h` 기준) contact sheet 후면·UV 가이드로
  사람이 하의 enum·색을 확인한다.
- 거부율(얼굴 미검출)이 현재 수준(14/97 ≒ 14%)에서 늘지 않는다.
- 테스트 전부 그린 + `validate_image` 전부 통과.
